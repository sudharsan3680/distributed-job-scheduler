# API Reference

Full interactive OpenAPI docs are auto-generated by FastAPI at `/docs`
(Swagger UI) and `/redoc` when the API is running — this file is a
human-readable index, not a duplicate spec.

Base URL: `http://localhost:8000`

## Auth model

Two separate auth schemes, deliberately not unified:

- **Human users** (dashboard) → `Authorization: Bearer <JWT>`, obtained from
  `/auth/login` or `/auth/register`. Scoped by organization membership + role
  (RBAC: owner/admin/member/viewer).
- **Workers / machine clients** → `X-API-Key: sk_...`, obtained once at
  project-creation time. Scoped to exactly one project. A worker process
  never needs, or gets, a human's login credentials.

All list endpoints are paginated (`page`, `page_size` query params) and
return `{items, total, page, page_size}`. All error responses are structured:
`{"error": {"code": ..., "message": ..., "details": [...]}}` (422s include
per-field validation `details`).

## Endpoints

### Auth
| Method | Path | Notes |
|---|---|---|
| POST | `/auth/register` | Creates user + their first organization (as owner) |
| POST | `/auth/login` | Returns JWT |

### Projects
| Method | Path | Notes |
|---|---|---|
| POST | `/organizations/{org_id}/projects` | Returns API key **once**, in the response body only |
| GET | `/organizations/{org_id}/projects` | List projects in an org |

### Queues (JWT-authenticated)
| Method | Path | Notes |
|---|---|---|
| POST | `/projects/{project_id}/queues` | Optionally embeds a `retry_policy` to create+attach in one call |
| GET | `/projects/{project_id}/queues` | List |
| PATCH | `/projects/{project_id}/queues/{id}` | Partial update: priority, concurrency, pause state, rate limit |
| POST | `/projects/{project_id}/queues/{id}/pause` \| `/resume` | |
| GET | `/projects/{project_id}/queues/{id}/stats` | Per-status counts + 1h throughput |

### Jobs (JWT-authenticated for CRUD; workers use the API-key endpoints below)
| Method | Path | Notes |
|---|---|---|
| POST | `/projects/{project_id}/queues/{qid}/jobs` | Create one job. `run_at` **or** `delay_seconds` **or** neither (= immediate) |
| POST | `/projects/{project_id}/queues/{qid}/jobs/batch` | Up to 1000 jobs in one call, grouped under a `Batch` |
| GET | `/projects/{project_id}/queues/{qid}/jobs` | Filter by `status`, `job_type`; paginated |
| GET | `/projects/{project_id}/jobs/{id}` | Full detail incl. executions + logs |
| POST | `/projects/{project_id}/jobs/{id}/cancel` | Only from a non-terminal state |
| POST | `/projects/{project_id}/jobs/{id}/retry` | Operator-triggered replay of a FAILED/DEAD_LETTER job |
| POST | `/projects/{project_id}/queues/{qid}/scheduled-jobs` | Create a cron schedule (validated via `croniter`) |
| GET | `/projects/{project_id}/queues/{qid}/scheduled-jobs` | List schedules |
| POST | `/projects/{project_id}/scheduled-jobs/{id}/pause` | Stop future firings |
| GET | `/projects/{project_id}/dead-letter-queue` | All DLQ'd jobs in the project |

### Workers (X-API-Key authenticated — this is the worker-process surface)
| Method | Path | Notes |
|---|---|---|
| POST | `/projects/{project_id}/workers/register` | Called once at worker startup |
| POST | `/projects/{project_id}/workers/{id}/heartbeat` | Called on a timer; also logs a `WorkerHeartbeat` row |
| POST | `/projects/{project_id}/workers/{id}/claim` | **The atomic claim.** Body: `{queue_names, max_jobs}` |
| POST | `/projects/{project_id}/jobs/{id}/start?worker_id=` | CLAIMED → RUNNING, opens the attempt's `JobExecution` |
| POST | `/projects/{project_id}/jobs/{id}/result?worker_id=` | Reports success/failure; drives retry-or-DLQ |
| POST | `/projects/{project_id}/workers/{id}/drain` | Mark draining (graceful shutdown signal) |
| POST | `/projects/{project_id}/workers/{id}/deregister` | Mark offline |
| GET | `/projects/{project_id}/workers` | List (API-key form) |

### Dashboard (JWT-authenticated)
| Method | Path | Notes |
|---|---|---|
| GET | `/projects/{project_id}/dashboard/health` | System-wide counters |
| GET | `/projects/{project_id}/dashboard/queues` | Per-queue stats, all queues at once |
| GET | `/projects/{project_id}/dashboard/workers` | Worker list (JWT form, mirrors the API-key one) |

### Live updates
| Path | Notes |
|---|---|
| `WS /ws/projects/{project_id}?token=<JWT>` | Receives `{"event": "...", ...}` frames: `job.created`, `job.running`, `job.completed`, `job.retry_scheduled`, `job.dead_letter`, `job.cancelled`, `job.retried`, `jobs.claimed`, `worker.registered`, `worker.offline`. The JWT is required as a query param; unauthorized connections are closed with code 1008. |

## Example: submit a job and watch it run

```bash
# 1. create a queue with an exponential retry policy
curl -X POST localhost:8000/projects/1/queues -H "Authorization: Bearer $JWT" \
  -d '{"name":"emails","max_concurrency":5,"retry_policy":{"name":"default","strategy":"exponential","base_delay_seconds":5,"max_attempts":5}}'

# 2. submit a job, run in 30s
curl -X POST localhost:8000/projects/1/queues/1/jobs -H "Authorization: Bearer $JWT" \
  -d '{"job_type":"sleep","payload":{"seconds":2},"delay_seconds":30}'

# 3. a worker (separate process) polls and claims
curl -X POST localhost:8000/projects/1/workers/1/claim -H "X-API-Key: $API_KEY" \
  -d '{"queue_names":["emails"],"max_jobs":5}'
```
